# 唤醒与端到端延迟调试（2026-11-18）

本次基于真实 Echo 采集、已归档的合成声学输入，以及用户参与的三次 Astero 呼叫调试。日期按 America/Los_Angeles；证据目录使用 UTC 时间。

## 已确认的问题和修改

1. **长时间监听的 KWS 历史状态影响命中。** 原实现对一段完整历史录音漏检，裁掉较早的背景后同一发音能命中。改为共享模型、8 秒寿命、4 秒交错的关键词流；保持原词表与阈值。原基准的首次唤醒离线命中由 3/5 变为 4/5，含重试由 4/6 变为 5/6；213.72 秒录音中目标窗口外没有匹配。这是小样本回放证据。
2. **单一麦克风通道存在互补性。** 新固定唤醒样本在通道 6 首发漏检，在通道 5 能命中；旧样本则有相反情况。不能据此认定某个通道普遍更好，也没有通过提高增益或扩大模糊别名掩盖问题。
3. **测试 TTS 发音本身不稳定。** 默认 Vivian 对孤立 Astero 的某些源 WAV 在进入扬声器前就无法命中。加英文说明能生成可检测样本，但后续随机生成仍有失败。验证工具现在记录并允许配置 `wake_style`；固定的已验证 WAV 用于可重复对照。这些输入修正不能当作真人唤醒率提升。
4. **句尾等待叠加。** Silero 内部静音保持从 0.5 秒改为 0.1 秒，服务端点等待从 1.5 秒改为 0.8 秒（`--end-silence` 可调）。四段已归档命令回放的端点提前 1.07–1.09 秒，ASR 文字均不变；覆盖 0.7 秒句中停顿后继续说话的测试。
5. **对话请求启动了无需使用的工具。** 每次 Codex 调用关闭 apps、plugins、shell snapshot、shell tool 和已配置 MCP 服务；保持原模型、认证、provider 与推理档位。降低推理档位的对照没有收益，未采用。四组交替文本调用平均 4.129 → 3.431 秒，另有波动。提示词缩短简单确认，同时保留复杂问题需要的解释。
6. **增加首次观察到播放状态的计时。** `first_playing_observed` 记录首次观察 Bridge `playing`；未观察到就结束则记 skipped。它是播放器状态代理值，不是物理首音测量。
7. **退出握手和尾帧。** 实机控制通道探测显示 `adb exec-out` 无法完成 stdin 交互（2 秒超时），`adb shell -T` 在 0.089 秒返回控制字符。设备 helper 输出 256 样本块、主机使用 160 样本帧，正常结束可能留下有效短帧；不得丢弃或掩盖为完整归档。第一次退出顺序修复的实机结果仍有不完整归档，作为未通过验收的中间结果保留。

## 用户实际发音

用户确认连续说了三次 Astero。对应归档在播报前离线命中三次，时间偏移约 2.22、4.45、7.00 秒。在线第一次已触发；第二次处于收集指令阶段，第三次处于 LLM 处理阶段，因此未重复唤醒。播报期间另有一次匹配，来源无法确认，排除在人声统计之外。

这说明这组三次实际发音可检测，不代表普遍准确率。当前服务仍为半双工：收指令、处理和播放时不接受再次唤醒，尚不支持打断。

## 最终部署验收与剩余问题

最终代码全量 130 项测试通过。真实设备独立退出探测耗时 0.0857 秒，103 帧共 16,384 个采样完整归档，包含有效短尾帧；证据为 `~/.local/share/astero/benchmarks/shutdown-probe.json`。

双通道离线回放覆盖约 259 秒合成测试录音，目标窗口之外没有匹配；固定唤醒的三次首发均命中，旧长监听样本也保持命中。含真人样本共 275.34 秒音频的处理耗时 18.05 秒，约为实时的 0.066 倍。证据为 `fixedwake-final-20261119T013909Z/dual-channel-audit.json`。这些结果不证明广泛环境中的误唤醒率。

**结论边界：** 唤醒与采集退出修复已在上述有限样本验证；问答整体可靠性仍未全部通过。首次优化对照的平均 25% 提速不能保证每轮稳定低延迟。最终三轮中出现一次 ASR 易混词和一次 LLM 错误，长回答的整段 TTS 生成与播放仍显著增加等待。对 LLM 用同一后端单独重试已成功（3.82 秒），未复现错误，原因尚未查清；保留 `llm-recheck.json`，不把这次诊断成功当作声学失败轮的通过。

服务已恢复并保持常驻监听。后续重点是 LLM 错误分类与有界恢复、ASR 易混词校准，以及流式回复/首音优化；当前仍不支持处理中或播报时打断。
